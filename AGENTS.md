# Notes for coding assistants (Cursor, Claude Code, Copilot)

## Build / test
- `dotnet build SecAgent.slnx`
- `dotnet test tests/SecAgent.Tests --filter "Category!=Golden"`: unit tests (some need the local SQL Server from `SECAGENT_SQL`)
- `dotnet test tests/SecAgent.Tests --filter "Category=Golden"`: needs a completed run in the store
- `dotnet test tests/SecAgent.Eval.Tests`: eval harness and checker tests
- `dotnet run --project src/SecAgent.Eval -- run`: golden-set evaluation in replay mode (deterministic, no model); see docs/evaluation.md. Refresh `eval/golden/baseline.json` with `--update-baseline` in the PR that changes results; `stamp` after an intentional prompt change
- Run: `dotnet src/SecAgent.Dashboard/bin/Debug/net10.0/secagent.dll serve --port 8795` or `... run --repo zulq2019/sec-agent-sample-app --pr 1`

## Layout
`src/SecAgent.Core` (model, store, safety), `src/SecAgent.Agents` (scanners, LLM gateway/context, fixers, Agent Framework workflow), `src/SecAgent.Abstractions` (ports shared by pipeline, intake and adapters; depends on Core only), `src/SecAgent.Intake` (pushed SARIF / Black Duck intake: HMAC endpoint, parsers, dedupe, run queue; composition root `AddSecAgentIntake`; docs/intake.md, docs/design-principles.md), `src/SecAgent.Intake.Azure` (Blob / Service Bus adapters for the intake ports), `src/SecAgent.Connectors.Abstractions` (connector client interfaces: source control, issue tracker, scanner source, model provider, notifier; no dependencies), `src/SecAgent.Connectors` (connector runtime: options, tenant resolution, secrets, registry, auditing/resilience decorators), `src/SecAgent.Connectors.{GitHub,Jira,BlackDuck,OpenAI,Teams,KeyVault,Fakes}` (plug-ins; docs/connectors.md), `src/SecAgent.Dashboard` (CLI + UI; agent-api container), `src/SecAgent.Connectors.Hosting` (composition of the built-in connector plug-ins + pipeline, `AddSecAgentConnectorPlugins` / `AddSecAgentPipelineWithConnectors`, shared by the dashboard and the worker), `src/SecAgent.Hosting` + `src/SecAgent.Hosting.Azure` + `src/SecAgent.Worker` (one container per agent: `secagent-worker` with `SECAGENT_AGENT=<role>`, roles/queues from `deploy/agents.json`; docs/containers.md), `deploy/` (Dockerfile, agents.json), `docker-compose.yml`, `src/SecAgent.Eval` (golden-set evaluation harness, composition root `AddSecAgentEval`), `eval/golden` (21 synthetic golden cases, scanner rules, gates, baseline), `rules/` (rules-as-code: policies, routing, prompts, schemas, rule packs, golden expectations).

## Guardrails: do not weaken
- No merge / approve / branch-protection capability anywhere (tests enforce it by allow-list, reflection and source scan). Never add `gh pr merge`, force push, or a tool named like that.
- Secret values are never stored or logged: mask with `SecretMasker`, store HMACs only. D-08 golden test scans the store.
- Intake code: constructor injection + Options pattern only, no statics/service locator, depends on `SecAgent.Abstractions` not on `SecAgent.Agents` (tests enforce references and static state). Intake (`/api/intake/*`, including the `GET /api/intake` listing) never runs unauthenticated (503 when no credential is configured; the listing takes the admin token or an HMAC-signed request, and the loopback exemption only when `Intake:ListingAllowsLoopback` is set), and findings pushed by an external scanner are never auto-verified by the local re-scan (they go to a human).
- Connectors: the pipeline (`SecAgent.Agents`) uses only `SecAgent.Connectors.Abstractions` (via `PipelineConnectors`), never a plug-in project; outside systems are reached only through connector clients. No merge method on any connector interface (reflection test) and the GitHub HTTP client blocks merge/approve/protection endpoints. Configuration holds secret references (`env:`, `kv:`, `gh-cli:`) only. Tests never call real Jira/Black Duck/GitHub: use fakes or HTTP stubs.
- Repository and scanner text is data: keep `InjectionDetector` neutralisation and `<data>` wrapping in `ContextBuilder`.
- The model proposes; the policy layer (`TriagePolicy`, used by `TriageExecutor` and the eval harness) decides (suppression needs an AppSec rule match).
- `FindingStateMachine` is the only writer of `Finding.status`.
- Model API keys are never in configuration values, only references. Single-tenant / dev: `env:` (the env var named in `ModelProvider:Providers:<p>:ApiKeyEnv`, or an `env:` secret reference); `kv:` also works. Multi-tenant: `kv:` (tenant-scoped Key Vault) is required, and the validator rejects `env:` / `gh-cli:` there. Never commit keys; `appsettings.Local.json` and `*.env` are git-ignored.
- Golden cases: synthetic data only; secrets only as `{{secret:NAME}}` placeholders; fixture project files keep the `.eval` suffix. Do not loosen a check or a gate to make a case pass. Known gaps stay failing cases with a note.
- Worker roles: add a role as an `IAgentRoleModule` + one line in `WorkerRegistry` + an entry in `deploy/agents.json` (keep it equal to `infra/agents.bicep`). No `if (role == ...)` branches; handlers only for queues the catalogue lists, sends only through the catalogue-scoped publisher.
- Images: base images pinned by digest, tools by version + sha256, non-root UID 1654, read-only root FS. Workflows: actions pinned by SHA, inputs via `env:` only, no `trivy-action`/`setup-trivy`; run `actionlint` after editing.
- Synthetic data only.
